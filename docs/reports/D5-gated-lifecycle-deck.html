The gated lifecycle

An AI-assisted development lifecycle for NBN Co, with a named gate on every task, run three ways and reviewed.

Team 2: Sidney Zeng, Ahmed Falulur Rahuman, Zac Clarkson, Zafir Hasan, Chirag Wadehra
Supervisor Ben Philip · Client representative Alessio Bonti · Repository nbn-sdlc-demo
In one slide

What we did, what we found

We opened NBN's eight-stage lifecycle into 44 tasks, gave each a colour, a gate and the thing that holds the gate, and grounded every stage in Google, Microsoft and DORA practice.

We then built the same feature three ways from one frozen brief and one base commit: AI only, copy and paste, and the gated lifecycle. An independent reviewer ran the same 17 criteria, 18 attacks, a mutation run and two seeded faults on each.

Two builds ticked all fourteen feature criteria, passed CI, and stored nothing. The gated build met 14 of 14, held all 18 attacks and caught both seeds. No automated gate caught the missing store in either of the others; a reviewer reloading the page did.

Part one

Why it matters

AI writes code that passes its own tests.

The problem

Green CI means the tests ran

24.2%

of AI-introduced issues still present at repository HEAD; security issues the most likely to survive (41.1%). Liu et al., 304,362 AI-authored commits, arXiv 2603.28592.

39–59%

accuracy of LLM-generated test assertions across two datasets. ACM TOSEM 2025.

45%

of the time models chose the insecure option across 80 tasks. Veracode 2025, vendor report, triangulated with Pearce et al. (about 40% of Copilot programs vulnerable).

An agent that writes the code and the tests passes its own tests. The question the lifecycle has to answer is who notices, and what makes them.

The brief

Eight stages, and a colour on each

NBN asked for a software development lifecycle that uses AI, across their eight stages, with a traffic-light view of where AI can act.

The workshop record (D2: June 2026, four days, two cohorts of about 32 to 35 NBN staff) gave a colour per stage. A colour per stage cannot be acted on: stage 6 is amber, so what does a developer do at 9 am?

What we changed

  • Colour moved from the stage to the task. 44 tasks.
  • Colour means who decides, not how much AI.
  • Every task names a gate and what holds it.
  • Stages 5 to 8 operated in full; 1 to 4 mapped and cited.

The gated lifecycle

A map and the gates that hold it.

Definition

A map and the gates that hold it

Colour

Who decides.

Red a human decides

Amber AI drafts, a human approves

Green AI runs, a deterministic check holds

Gate

What must be true before the next task starts. Written as a countable condition.

"Every commit passes pre-commit and commit-msg." Not "commits should be clean."

Holder

What makes the gate hold. One of six. Every task names one.

An instruction file is no gate.

The map is NBN's eight stages opened into 44 tasks. Stages 5 to 8 are operated and were tested; stages 1 to 4 are mapped on Google's Design Sprint and cited.

Holder

Six things can hold a gate

Hook (git)lefthook pre-commit: secret scan, placeholders, prettier, eslint. commit-msg: Conventional CommitsBinds every tool and person who ran pnpm install
Hook (agent)copilot-guard.json denies git push, --no-verify, hook changesBinds one tool. Fails open after 10 s. Nothing binds ChatGPT in a browser
CI check (required)AI Declaration, AI Attribution, Lint & Typecheck, Frontend Tests, Backend Unit Tests, Security ScanBlocks the merge while the ruleset lists it
CI check (advisory)Mutation run on every pull requestReports. Blocks nothing
Platform ruleThe main ruleset: two approving reviews, squash only, no force push, no deleteEveryone. Changed only by an admin
HumanApprove the plan (6.1). Approve the merge (6.4). Judge whether the tests would notice (7.4)What no script can decide
No gateCLAUDE.md, copilot-instructions.md, AGENTS.md, prompts, skills, the agent's own summaryRead and maybe complied with. In our dry run the agent "stopped and waited" by choice
The map

Eight stages, 44 tasks

Stages 1 to 4 scaffolded on Google's Design Sprint; not operated in this paper. Work enters stage 5 through the entry gate: an approved business case, stories with checkable criteria, recorded architecture decisions, agreed journeys and design.

The count did not spread. The kind did.

  • Two lanes shipped a feature that forgets everything on reload and passed every automated check.

Part eight

Limits, and what a team takes away

Limits

What this does not show

  • Three builders, one per lane, one feature each. A method effect and a builder effect cannot be separated. Lane C's builder also wrote the gated lifecycle he built with.
  • Four-hour builds on student plans. Stages 1 to 4 and 8.2 to 8.6 are on the map and were never run.
  • No NBN developer was interviewed. Two practitioners, one workshop record, one supervisor's reviews.
  • The keyboard check on all three previews is partial; the review tooling cannot drive native date pickers.
  • On the main repository itself only one CI check is required; the six-check gate was proved on the trial two repositories.
  • The prediction was not supported on count. The paper says so.
For a team

What you install, what you decide

Install, once

  • lefthook: secret scan, lint, format, Conventional Commits
  • The agent hook for the tool you use: no push, no hook bypass
  • Six CI checks and the pull request template with the AI declaration
  • The main ruleset: two approvals, squash only, checks required

Decide, every time

  • 5.3 The issue has testable criteria and an out-of-scope list, or it goes back
  • 6.1 No code before a person approves the plan
  • 6.4 Two people who did not write it
  • 7.4 Would the tests fail if the code were wrong? Reload the page
