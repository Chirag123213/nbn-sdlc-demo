## 1. In one paragraph

FR-01 shows how an authenticated fault report moved from approved criteria through implementation, separate agent review, automated checks, human approval and deployed verification. The useful result is the trace: review exposed test gaps, tests caught isolated seeded faults, and later deployed testing still found an acceptance problem. Readers can use that trace to distinguish a passing test suite, permission to merge and acceptance of deployed behaviour. Sprint 3 strengthened the required checks on main and proposed further repository fixes, but the retained evidence does not close the AC2 correction and independent retest requirement. This chapter therefore supports reuse of the demonstrated steps while carrying the remaining gaps into section 5.

### 3.4 What this does not show

This is a single feature run with mixed evidence. Mocked storage and mutation tests demonstrate test behaviour; the local Firebase observations and deployed browser checks answer different questions. The agent review was separate in context, and its seeded-fault discovery was not blind. The preliminary mutation run used different source and mutant counts, so only the retained same-scope pair supports the reported focused-revision comparison.

FR-01 provides no measured productivity uplift, per-gate cost or production-reliability rate. Current ruleset configuration establishes which jobs are required now, without rewriting the historical enforcement claim. PR #72's successful checks establish a reviewed implementation candidate, while its open state prevents treating it as a fix deployed from main. Actionable limits and acceptance dependencies are collected in section 5.

### 3.5 What the manual takes from it

- **Tasks 5.2, 5.3 and 6.1:** check the agent worktree's environment before handoff; record the approver, full date/timezone, criteria, exclusions and implementation authorisation together.
- **Tasks 6.2 and 6.3:** record the Copilot lane, exposed model/version or an explicit unavailable value, session, source commit and prompt location. Do not infer the model from a co-author trailer.
- **Tasks 6.3 and 6.4:** give reviewers an AC matrix and indexed evidence. Date PR-size counts and record explicit scope exceptions before bundling dependency work into a feature.
- **Tasks 7.1, 7.3 and 7.4:** use the separate review to find weak assertions; retain mutation scope/counts, seeded-fault results and the human judgement separately. Say whether the reviewer knew the seeded fault types.
- **Tasks 6.4, 7.2 and 7.5:** inspect the live ruleset before calling CI required. Distinguish the final head from the first push, and historical audit results from a current audit.
- **Tasks 8.1 and 8.3:** connect the tested URL to a deployed main commit, then record the independent acceptance result. For AC2, distinguish input truncated by the browser from an oversized payload reaching the server; verify rejection creates no record.
- **Task 8.6:** turn findings into scoped fixes, then record whether each is proposed, merged, configured or actually exercised. Capture stage-level usage prospectively in the next run.
