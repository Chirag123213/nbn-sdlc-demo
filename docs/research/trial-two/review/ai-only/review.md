## 1. In one paragraph

This is the independent review record for the lane A (AI only) build by Ahmed Falulur Rahuman, reviewed against the frozen commit `f1611e0` and never against anything pushed later. On the preview the matching logic is right in every fixture case: the second-storey and pit refusals hold, no match is invented, scheduling works, and the badges survive greyscale and the keyboard. But the build keeps the request, the match and the dispatch in browser memory only. Nothing is written anywhere, the dispatch page needs no sign-in, and a reload loses the request. T2-AC01 and T2-AC11 fail on that, AT12 lands, and the Firestore and server attacks have nothing to hit. The tests cover the matching function well (24 of 28 covered mutants killed) and the component less so; seed S2 is caught. Three findings count toward the registered prediction, all escaped.

#### 3.4 What this does not show

- Keyboard operation of the native date and radio controls was not exercised, because the review tooling's synthetic keys do not drive them. The pass on TJ13 rests on the controls being unstyled native inputs with labels and no custom handlers. A human keyboard run would close it.
- AT15 is partial: the secrets scanner the protocol names was not available locally, so the local check is a grep and the CI result is the only gitleaks run.
- The mutation score covers the configured scope, which includes untouched base files. Both figures are given so the base's zero-coverage files do not read as the build's.
- Screenshots were taken through the browser pane at reduced scale; the page text saved beside them is the exact record.

#### 3.5 What the manual takes from it

- A green pull request with fourteen ticked criteria and a working preview said nothing about whether anything was stored. The gate that would have caught it is a reviewer raising a request, reloading, and looking for it. Put that step in the review checklist for any feature whose criteria say "records" or "visible afterwards".
- A page outside the `(dashboard)` route group is public. The base's auth sits in that group's layout, so a new top-level route skips it without anyone choosing to. The checklist should ask where a new page sits.
